# 🤝 Contributing to DSA Mastery Plan 2026

Thank you for your interest in contributing to this 150-day DSA mastery roadmap! This is a community-driven project, and we welcome improvements, suggestions, and resources.

---

## 📋 Ways to Contribute

### 1. **Improve Existing Resources**
- Found a broken link? Submit a fix!
- Better explanation for a pattern? Enhance it!
- More practice problems? Add them!

### 2. **Add New Content**
- Suggest better YouTube tutorials
- Contribute alternative problem explanations
- Add company-specific interview tips
- Share your personal learning insights

### 3. **Fix Issues**
- Report unclear sections
- Point out outdated resources
- Suggest better organization
- Fix typos or formatting

### 4. **Share Your Progress**
- Create your own learning log in `/logs`
- Document your postmortem analyses in `/postmortems`
- Share what worked for you

---

## 🛠️ How to Contribute

### Step 1: Fork the Repository
```bash
git clone https://github.com/YOUR_USERNAME/dsa-mastery-plan-2026.git
cd dsa-mastery-plan-2026
```

### Step 2: Create a Branch
```bash
git checkout -b feature/your-improvement-name
# or
git checkout -b fix/issue-name
```

### Step 3: Make Changes
- Edit markdown files with clear, concise language
- Update links if resources have changed
- Keep formatting consistent with existing content
- Test links before submitting

### Step 4: Commit Your Changes
```bash
git add .
git commit -m "feat: add better explanation for DP patterns"
# or
git commit -m "fix: update broken Striver link"
```

### Step 5: Push to Your Fork
```bash
git push origin feature/your-improvement-name
```

### Step 6: Create a Pull Request
- Go to the original repository
- Click "New Pull Request"
- Select your branch
- Write a clear description of changes
- Submit!

---

## 📝 Contribution Guidelines

### For Code Changes
- Keep HTML/CSS/JS consistent with existing style
- Maintain dark theme and responsive design
- Test on mobile devices
- Add comments for complex logic
- Update related documentation

### For Documentation Changes
- Use clear, beginner-friendly language
- Provide direct links to resources
- Include problem numbers (e.g., LC 15 for LeetCode problem)
- Add emoji indicators (⭐ for essential, 🔥 for hard)
- Keep consistency with formatting

### For Resource Additions
- **YouTube**: Full playlist or video URL with timestamp
- **LeetCode**: Include problem number and direct link
- **Articles**: Full URL and brief description
- **Tools**: Mention how it helps learning

## 📚 Content Standards

### README & Main Docs
- Use clear headings (H2, H3, H4)
- Include relevant emojis for visual hierarchy
- Link to related sections
- Keep paragraphs concise

### Code Comments
- Explain the "why", not just the "what"
- Use JSDoc format for functions
- Mark complex sections clearly

### Resource Links
- Verify links work (no 404s)
- Include timestamps for long videos
- Add difficulty/duration info when available

## 🐛 Reporting Issues

Found a problem? Please report it!

### When Reporting:
1. **Be Specific**: Describe exactly what's wrong
2. **Include Context**: What were you trying to do?
3. **Share Links**: If it's about a resource, link to it
4. **Suggest Solutions**: If you have ideas, share them!

### Issue Template:
```markdown
**Title:** Clear, concise issue title

**Description:**
What's the problem? Be specific.

**Expected Behavior:**
What should happen?

**Actual Behavior:**
What actually happens?

**Screenshots/Links:**
Relevant images or links

**Suggestions:**
Any ideas for fixing it?
```
